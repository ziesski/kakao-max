# 방 허가와 운영자 제한

2026-10-25 🟡 단위·격리 MCP 통합 테스트 기준. 새 구현으로 실계정 전송·배포는 하지 않았습니다.
전체 도구는 [현재 계약](../tool-contract.md), 확인 수단은 [승인 운영](passkey-approval.md)을 읽으세요.

권한은 두 층입니다. `KAKAO_ROOM_CEILING`·pause·속도 제한이 운영자 상한이고,
방별 전송 허가와 읽기 규칙·일회성 읽기 허가가 사람의 권한입니다. 상한은 승인이 아닙니다.

전송 허가는 `recipient_permissions`가 유일한 저장소입니다. 첫 메시지의 확인 창에서 코드와
“앞으로 묻지 않기”를 함께 선택하거나, 방 읽기 확인 창에서 “이 방에 답장도 묻지 않고 보내기”를 선택하거나,
AI가 `request_permission`을 type send로 요청하고 사람이 승인합니다. 첫 사진의 확인 창은 이 전송 허가를 묻습니다.
`KAKAO_RECIPIENT_DAILY_LIMIT`(1–500, 기본 50) 안에서 그 방의 후속 메시지·사진을 보냅니다.
허가는 문구를 제한하지 않습니다. 고정 문구 사전 승인은 제거됐습니다.

`list_permissions`로 허용한 방을 확인하고 `revoke_permission`에 permissionId `recipient:<chatId>`를
전달해 철회합니다. 철회는 즉시 적용되며 새 일반 전송은 다시 승인을 요청합니다.
이미 따로 승인된 단일 작업의 승인이나 전송 기록을 지우지는 않습니다.

내용 조회는 type room_access로 읽기 규칙을 요청합니다. manual 방의 한 번 읽기는 type read로 요청합니다.
기본 read_messages·20개·1회·10분입니다. 허가한 방은 안 읽은 메시지가 있어도 읽으며, 읽음 표시는 보내지 않습니다.
전송 허가는 조회나 읽음 표시를 허용하지 않습니다. 읽음 표시는 chats 묶음의 mark_read로 별도 승인합니다.

삭제·나가기·전달·변경 등은 각 작업 승인을 유지합니다. 사진 한 장만 승인하려면 패스키 미리보기를 쓰고,
확인 창에서는 정확한 방의 전송 허가로 승인합니다. `KAKAO_NOTIFY_CHAT_ID`는 데몬 자체 승인 알림 전용이고
에이전트 발신은 그 방에도 허가가 필요합니다.
알림 방도 `KAKAO_ROOM_CEILING` 밖이면 발신이 차단됩니다. 상한을 설정했다면 알림 방을 포함할지는 운영자가 결정합니다.

감사 JSONL은 시각·결정·사유·텍스트 길이와 `targetRef`를 기록합니다. `targetRef`는 실행 중 생성한 비밀 키로
대상을 HMAC 처리한 값이며 같은 실행 안의 시도만 연결할 수 있습니다. 원본 `chatId` 필드는 기록하지 않고,
재시작하면 참조가 바뀝니다. 이전 로그를 자동으로 정화하거나 삭제하지는 않습니다.

`get_status`에서 제한·pause·승인 수단을 확인합니다. POLICY_DENIED이면 허가를 반복 요청하지 말고
원인을 확인합니다. OPERATION_STALE은 다시 검토하고, 결과 불명은 자동 재전송하지 않습니다.
