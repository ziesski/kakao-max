# 실험적 태블릿 연결

Linux에서 Android 태블릿의 보조 기기 인증 방식으로 연결하는 선택지입니다. 기존 PC 연결 방식은 기본값입니다. 실제 태블릿 하드웨어나 Android 실행 환경은 데몬 실행에 필요하지 않습니다.

**상태: 🟡 단위·fixture 검증.** 인증 요청 형식, 기기 키 유지, 재로그인, 설정 저장과 충돌 중단을 검사했습니다. 카카오 서버의 실제 인증, 휴대폰·공식 PC·이 데몬의 동시 접속, Android 경로의 친구·프로필·첨부 호환은 ❓ 미검증입니다. 기존 기능 표의 실계정 검증은 PC 연결에 해당합니다.

## 새 설치에서 선택

Linux 설치 마법사의 `연결 기기 유형`에서 `tablet`을 입력합니다. Enter는 기존 `pc`입니다. 마법사는 새 기기 키를 만들고 휴대폰 승인을 기다립니다. 인증이 중단되면 유형과 키를 보존하므로 다시 실행해 이어갈 수 있습니다. 기존 설치를 자동으로 변경하지 않습니다.

수동 등록은 **기존 자격 증명이 없는 별도 디렉터리**의 `.env.local`에서 `KAKAO_DEVICE_TYPE=tablet`을 설정하고 등록 프로그램을 실행합니다. 이메일과 비밀번호는 비공개 설정 파일에만 넣고 명령 인자로 전달하지 마세요. 인증번호는 사람에게 직접 표시됩니다. 성공하면 `KAKAO_REGISTERED_DEVICE_TYPE=tablet`과 별도 기기 키·토큰을 저장합니다. 자격 증명이 이미 있으면 등록 프로그램은 새 등록을 거부합니다.

## 기존 PC 설치와 전환

기존 키·토큰에 `KAKAO_DEVICE_TYPE=tablet`을 덧붙여 전환할 수 없습니다. 유형 정보가 없는 기존 자격 증명은 `pc`로 취급하고, 저장된 유형과 요청 유형이 다르면 네트워크 접속 전에 `CONFIG_INVALID`로 중단합니다. `KAKAO_REGISTERED_DEVICE_TYPE`을 직접 고쳐 기존 키를 재사용하지 마세요.

시험에는 별도 설정 파일, 데이터 디렉터리, 로컬 소켓을 사용합니다. 같은 기기 키로 데몬을 두 개 실행하지 마세요. 기존 데몬과 공식 PC가 PC 연결을 공유할 수 있다고 가정하지 말고, 사용자가 먼저 기존 데몬의 중단 여부를 결정해야 합니다.

태블릿은 보조 기기 슬롯을 사용하므로 이미 등록된 보조 기기와 충돌할 수 있습니다. 슬롯 충돌은 휴대폰의 등록 기기 목록을 직접 확인하세요. tablet 경로는 강제 로그인이나 기존 기기 해제를 수행하지 않습니다.

## 버전과 재로그인

초기 프로필은 Android 앱 `25.9.2`, OS `13`, API `33`, 모델 `SM-T870`입니다. 이 버전의 현재 서버 수락 여부는 미검증입니다. `KAKAO_APP_VERSION`을 설정하면 등록과 LOCO, 자동 재로그인에 같은 버전을 적용합니다. `KAKAO_CLIENT_OS`는 tablet일 때 `android`, pc일 때 `mac`만 허용합니다.

자동 재로그인은 기존과 같이 사용자가 비밀번호 저장을 선택한 경우에만 활성화됩니다. 저장한 유형과 기기 키로 일반 로그인을 하며 강제 로그인·재등록을 하지 않습니다. 충돌이나 새 인증 요구가 오면 중단하고, 기존 횟수 제한을 유지합니다.

## 실제 검증 순서

1. 휴대폰의 등록 기기 목록에서 기존 보조 기기를 확인합니다. 시험 중 기기 해제가 필요하면 사용자가 직접 결정합니다.
2. 공식 PC가 정상 연결된 상태에서 별도 tablet 자격 증명을 등록합니다. 충돌하면 강제로 재시도하지 않습니다.
3. 시험 데몬 하나를 연결하고 휴대폰과 공식 PC가 계속 연결되어 있는지 확인합니다.
4. 사용자가 지정한 시험 방에서 수신을 확인합니다. 메시지 전송은 사람 승인 후에만 시험합니다.
5. 시험 데몬만 종료·재시작해 같은 기기 유형과 키가 유지되는지 확인합니다.
6. 친구·프로필·첨부는 각각 별도 검증합니다. 확인 전에는 PC 기능의 검증 결과를 tablet에 적용하지 않습니다.
