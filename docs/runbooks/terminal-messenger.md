# 작은 터미널 메신저

`kakao chat`은 사람이 방을 고르고 대화할 수 있는 간단한 화면입니다. 기존 명령형 CLI와 MCP는 그대로 사용합니다. 조회와 전송 모두 기존 MCP 도구와 데몬의 ask/trust 정책을 사용합니다. 새 계정 로그인이나 데몬 재시작은 하지 않습니다.

저장소에서 실행:

```bash
npm run kakao -- chat
```

터미널을 가로 72칸·세로 14줄 이상으로 준비하세요. 원격 데몬은 [SSH 연결 안내](cli-chat-shell.md)를 따라 로컬 포트를 연결하고 `MCP_PORT`를 지정합니다.

## 연결 준비

메신저는 명령형 CLI와 같은 MCP 연결 하나만 사용합니다. 원격 서버에는 기존 SSH MCP 터널만 필요합니다. 별도 사용자 소켓·소유자 프록시·추가 카카오 로그인은 필요하지 않습니다.

화면 헤더에 데몬의 현재 `ask` 또는 `trust` 모드를 표시합니다. 모드는 CLI 한 번의 실행에 붙이는 권한 상승 플래그가 아니라 데몬 전체 설정이며, 연결된 AI에도 동일하게 적용됩니다. `chat`은 모드를 바꾸지 않습니다. 설정과 위험 설명은 [에이전트 모드 안내](../designs/agent-mode-and-layers.md)를 참고하세요.

## 사용 흐름

1. 왼쪽 목록에서 방 이름을 검색하거나 위·아래 방향키로 선택합니다.
2. Enter를 누르면 오른쪽에 최근 30개를 표시하고 입력창으로 이동합니다.
3. 문장을 작성하고 Enter로 전송합니다. 여기서는 `ls`나 `cd`도 메시지 본문으로 보냅니다.
4. 선택한 방의 새 메시지는 MCP `read_messages`의 recent 피드로 약 2초마다 조회해 반영합니다. 작성 중인 문장은 유지합니다. 전송 중에는 추가 입력을 잠시 막아 작성 내용이 사라지거나 중복 제출되지 않게 합니다.
5. Tab 또는 Esc로 방 목록으로 돌아갑니다. 다른 방을 열면 작성 중인 문장은 초기화합니다.

PgUp/PgDn으로 현재 화면에 쌓인 대화를 스크롤하고, Ctrl+R로 현재 방의 최근 30개 또는 방 목록을 다시 조회합니다. Ctrl+C로 종료하면 커서·입력 모드를 복구하고 MCP 연결을 닫습니다. 붙여넣기 모드를 지원하는 터미널에서는 여러 줄을 붙여넣어도 전송하지 않고 한 줄로 합쳐 입력창에 넣습니다. 전송하려면 이후 Enter를 직접 누릅니다.

방을 열거나 Ctrl+R로 대화를 다시 조회할 때는 해당 방의 읽음 상태를 서버에서 먼저 갱신합니다. ask 모드에서 안읽음 제한으로 방 열기에 실패했다면 휴대폰에서 그 방을 읽은 뒤 Ctrl+R을 누르면 마지막으로 열려고 했던 방을 다시 조회합니다. 서버에서도 안읽음이 남거나 읽음 상태를 확인할 수 없으면 계속 차단하며, 이 갱신은 읽음 표시를 보내지 않습니다.

텍스트 대화의 최소 기능입니다. 파일·사진 첨부, 음성 통화, 자동으로 과거 기록을 계속 불러오는 기능은 포함하지 않습니다. 기존 MCP 피드는 과거 메시지의 삭제·수정을 모두 자동 반영한다고 보장하지 않으므로 Ctrl+R로 최근 기록을 다시 조회합니다. 화면에 보관하는 메시지는 최대 200개이고, 오래된 모든 과거 기록이 조회된다고 보장하지 않습니다. 연결·조회 오류가 발생하면 자동 갱신을 멈추고 상태를 표시합니다. Ctrl+R로 재조회하거나 종료 후 다시 연결하세요. 자동 재로그인이나 전송 재시도는 하지 않습니다.

## 권한과 전송 결과

조회도 기존 MCP 읽기 정책을 따릅니다. `ask`에서는 방 권한·승인과 이미 읽은 방 제한이 적용됩니다. 승인 코드를 입력해도 안읽은/읽음 상태 불명 방 제한은 별도로 남습니다. `trust`에서는 안읽은 방 제한이 해제되지만 명시한 deny 등 방 규칙과 운영자 상한은 유지됩니다. 두 모드 모두 조회가 읽음 표시를 보내지는 않습니다.

“이번만 읽기”를 선택하면 자동 갱신을 멈춥니다. Ctrl+R로 다시 요청할 수 있습니다. 계속 읽기 허가가 있는 방은 정책 범위 안에서 갱신하며, 이후 권한이 거절되면 갱신을 멈추고 이유를 표시합니다.

전송은 기존 MCP 정책·방 허가·일일 한도·사람 승인을 그대로 따릅니다. 일반 모드에서 필요한 승인 코드를 직접 입력하고, 빈 코드·Esc로 거절·취소할 수 있습니다. 후속 전송 허용 질문의 기본값은 N입니다. 읽기 승인 역시 일반 모드의 확인 창에서 처리합니다.

전송 완료 표시는 데몬의 처리 응답이며 상대방의 실제 도착과 구분합니다. 결과가 불확실하면 입력 내용을 유지하고 새 전송을 막습니다. 화면을 다시 시작해서 같은 내용을 보내면 별도 요청이므로, 먼저 카카오톡과 기존 작업 상태를 확인해야 합니다.

## 촬영

```bash
npm run kakao -- chat --demo --show-room "공개할 방 이름"
```

다른 방 이름·발신자를 가명으로 표시하고 지정한 공개 방만 엽니다. 시스템 알림의 원본 메타데이터도 표시하지 않습니다. 공개 방의 일반 메시지 본문, 인원·안읽음 수치까지 익명화하는 기능은 아닙니다. 계정 정보가 포함될 수 있는 승인 화면은 촬영 모드에 표시하지 않으므로 필요한 전송 승인을 녹화 전에 일반 모드에서 확인하세요. 촬영 모드 자체는 권한을 바꾸지 않습니다.

[명령형 대화 셸](cli-chat-shell.md)은 `kakao shell`로 따로 실행할 수 있습니다.

공통 MCP 연결과 대화 모델은 [터미널 메신저 설계](../designs/terminal-messenger.md)를 참고하세요.
